# remnanode-setup

Один скрипт, который поднимает ноду [Remnawave](https://docs.rw) на чистой Ubuntu и чинит то, из-за чего ноды обычно ломаются: занятый apt, занятые порты, просроченные сертификаты, нехватка памяти.

## Быстрый старт

1. В панели добавьте ноду и скопируйте `docker-compose.yml`, который она покажет.
2. Если на ноде будет Hysteria2 или другой TLS-инбаунд, заведите A-запись домена (например `de15.example.com`) на IP сервера.
3. На сервере под root:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/OWNER/remnanode-setup/main/install.sh)
```

Скрипт откроет редактор: вставьте туда compose из панели (или только `SECRET_KEY=...`), сохраните (`Ctrl+O`, `Enter`, `Ctrl+X`). Затем он спросит домен и сделает всё остальное, а в конце покажет логи ноды (`Ctrl+C` закрывает логи, нода продолжит работать).

Без вопросов, например для автоматизации:

```bash
SECRET_KEY='eyJ...' bash install.sh -y --domain de15.example.com
```

Скрипт можно запускать повторно: он доделывает недостающее и ничего не ломает. `--dry-run` показывает, что будет сделано, ничего не меняя.

## Команды

| Команда | Что делает |
|---|---|
| `install` (по умолчанию) | полная установка или донастройка |
| `cert --domain X` | выпустить или починить сертификат и его автопродление, например на уже работающей ноде |
| `status` | проверка: нода, порты инбаундов, WARP, сертификаты, ядро, память, диск. Ничего не меняет |
| `update` | обновить образ ноды и перезапустить её |

Опции: `--domain`, `--email`, `--secret-key-file FILE`, `--new-key`, `--node-port`, `--inbound-ports "443/tcp,9997/udp"`, `--no-warp`, `--warp-port`, `--no-swap`, `--firewall --panel-ip IP`, `--no-logs`, `--dry-run`, `-y`. Подробности: `bash install.sh --help`.

## Что делает `install` и зачем

| Шаг | Зачем |
|---|---|
| Ждёт освобождения apt, доделывает прерванный dpkg, ставит пакеты без интерактивных вопросов | на свежем VPS apt первые минуты занят unattended-upgrades, а needrestart задаёт вопросы посреди установки |
| Docker через get.docker.com, при неудаче — `docker.io` и `docker-compose-v2` из репозитория Ubuntu | get.docker.com не всегда сразу поддерживает только что вышедшие версии Ubuntu |
| Compose из панели плюс `volumes` с сертификатами и ротация логов контейнера | ключ, порт, образ и любые дополнительные переменные из панели сохраняются; прежний файл остаётся рядом как `.bak-*` |
| Сертификат Let's Encrypt с продлением, которому не мешает занятый 80-й порт | см. ниже |
| Cloudflare WARP в режиме proxy на `127.0.0.1:40000` | для outbound `warp` в профиле. Режим proxy включается до подключения, иначе WARP забрал бы весь трафик сервера вместе с SSH |
| Ядро: BBR и fq, UDP-буферы 16 МБ, conntrack 262144 с тайм-аутом 2 ч, резерв портов сервисов | BBR ускоряет TCP-протоколы на линиях с потерями; quic-go (Hysteria2) просит UDP-буфер около 7 МБ; по умолчанию conntrack держит запись 5 суток и забивается «мёртвыми» мобильными клиентами; без резерва исходящее соединение может занять порт сервиса, и после перезапуска он не поднимется («address already in use») |
| Swap 2 ГБ, если RAM меньше 8 ГБ и swap нет | без swap ядро при нехватке памяти убивает процессы (OOM) |
| journald не больше 300 МБ | без лимита журналы разрастаются на гигабайты |
| NTP | синхронизация времени |
| Сверка портов инбаундов из профиля с тем, что реально слушается | ловит «порт занят другим процессом» и «Xray не смог открыть порт» |
| Если ufw уже включён, открывает порт ноды и инбаунды | частая причина статуса «нода offline» после установки |

### Сертификат и порт 80

certbot работает на своём свободном порту (8089 или следующем). Только на время проверки Let's Encrypt правило iptables перенаправляет входящий `:80` на этот порт. Под правило попадают только адреса самого сервера, исходящий трафик контейнеров оно не трогает. Сразу после проверки правило снимается, даже если проверка не прошла. Поэтому неважно, кто держит 80-й порт: nginx, apache, HestiaCP или docker. Ни один сервис не нужно ни останавливать, ни освобождать, а продление переживает появление веб-сервера в будущем.

После продления хук копирует сертификат в `/etc/certs/remna/` (этот каталог смонтирован в ноду) и перезапускает ноду. В профиле панели пути к сертификату одинаковые на всех нодах:

```
/etc/certs/remna/fullchain.pem
/etc/certs/remna/privkey.pem
```

Чтобы перевести на такую схему ноду, где сертификат уже есть, но продлевается иначе или уже истёк:

```bash
bash install.sh cert --domain fl1.example.com
```

Проверить продление в любой момент:

```bash
certbot renew --dry-run
```

## Firewall

По умолчанию скрипт firewall не включает, чтобы случайно не закрыть доступ к серверу. С `--firewall --panel-ip <IP панели>` он включает ufw: SSH (порт берётся из `sshd -T`), 80, 443, порты инбаундов, а порт ноды открывает только для IP панели. Если у провайдера есть свой firewall (security group), порты нужно открыть и там.

## Что создаёт скрипт

```
/opt/remnanode/docker-compose.yml            (права 600: внутри SECRET_KEY)
/etc/certs/remna/                            сертификат для ноды
/usr/local/lib/remnanode-setup/acme-*.sh     хуки certbot
/etc/sysctl.d/60-remnanode.conf              настройки ядра (/etc/sysctl.conf главнее)
/etc/modules-load.d/remnanode.conf, /etc/modprobe.d/remnanode-conntrack.conf
/etc/systemd/journald.conf.d/60-remnanode.conf
/swapfile                                    если swap не было
/var/log/remnanode-setup.log                 лог всех запусков скрипта
```

## Если что-то не так

```bash
bash install.sh status
```

- **Нода offline в панели.** Порт ноды (по умолчанию 2222) должен быть открыт для IP панели: в ufw и у провайдера.
- **Инбаунд «не слушается».** Порт занят другим процессом (`ss -ltnup | grep :ПОРТ`) или в профиле ошибка. Смотрите `docker logs remnanode`.
- **HY2: `certificate has expired`.** Выполните `bash install.sh cert --domain <домен ноды>`.
- **В `status` congestion control не bbr.** Его перекрывает строка в `/etc/sysctl.conf`.

Проверено на Ubuntu 26.04: shellcheck без замечаний, `--dry-run` и `status` на работающей ноде. Перенаправление `:80` проверено против тестового сервера Let's Encrypt на сервере, где порт 80 занят nginx'ом.
